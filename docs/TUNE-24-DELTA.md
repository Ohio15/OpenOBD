# What tune #24 actually changed

**2010 Chevrolet Silverado 1500 5.3L** — VIN 3GCRKTE35AG150432

Stock baseline: `stock-10.13.24.hpt` (sha256 `0c108cea1fb037ac…`)  
Tune: `#24 - Claudes Edit 8.7.26`

> Generated by `tools/delta_report.py` from `data/2010_silverado_delta_stock_to_24.json`. Do not hand-edit.

## The answer

**Tune #24 changed 11 parameters.** Every one of them is load-bearing for drivability; there are no incidental edits.

1. **The axle ratio, in all three places it is stored** — 3.08 → 4.11.
2. **Tyre rolling circumference, both axles** — 2475 → 2742 mm.
3. **All six WOT shift-speed schedules in the TCM** — mostly rescaled to ≈0.83× stock, with one deliberate exception noted below.

Those three groups are one coherent edit: the truck physically got 4.11 gears and 35" tyres, #24 told both controllers so, and then pulled the full-throttle shift speeds down so the engine still shifts near peak power instead of running into the limiter on the taller tyres and shorter gears.

The exception is worth seeing, because it is the signature of a deliberate hand edit rather than a blanket rescale: on `TCM:15010`, the everyday Normal schedule, the **1-2 upshift was raised** 33 → 35 mph (+6.1%) and the 2-1 downshift 30 → 31 mph, while 2-3 and above were pulled down 12–16%. Every other table was scaled down uniformly. Someone chose to hold first gear slightly longer from a standstill on the daily schedule and only then start shortening the rest.

**#24 did not touch anything else that both sides cover.** All 369 scalars and 240 of the 246 comparable tables the #24 sweep holds are identical to stock.

### AFM/DoD: #24 did *not* disable it

`ECM:246 DoD Enable` reads **0 ("Disable")** in the genuine October-2024 pre-tuning read. AFM was **already disabled before #24 existed**.

The tune is named "4.11 Gears, DOD Delete, Shift Points", so the DOD-delete half of that name describes a state #24 inherited, not a change it made. Any delta that reports #24 disabling AFM is wrong, and this is the check that catches it.

## How this was derived, and what would have made it wrong

### Join key

`(module, param_id) -- never the display name`. Three traps make a name match produce false results:

- `Final Drive Ratio` exists as **both** `ECM:9050` and `TCM:5004`. A name match collapses two distinct parameters into one.
- The tune sheet calls `ECM:246` *"DoD (AFM) Enable"*; VCM Editor calls it *"DoD Enable"*. An exact-name match scores it **MISSING**.
- Neither #24 file carries a `module` field at all, so the module had to be derived before the key could even be formed.

Module derivation: stock's `param_id → module` map has **zero cross-module collisions**, and the #24 table file embeds an `[ECM] id N` tag in its notes. The two agree on **245/245** overlapping tables with zero conflicts, so the derivation is corroborated rather than assumed.

### The rounding trap that nearly produced 11 false changes

The stock sweep stores values as VCM Editor *displayed* them; the #24 sweep stores full float precision off the calibration:

| Stock displays | #24 holds | Float delta | Truth |
|----------------|-----------|-------------|-------|
| `6,042` | 6041.924736342039 | −0.075 | same value |
| `19.9688` | 19.96875 | −0.00005 | same value |
| `16.2` | 16.25 | +0.05 | same value |
| `33` | 35.000674187743584 | +2.0 | **real change** |

A half-ULP float tolerance called 16 tables changed; 11 of those were pure display rounding. Equality is instead decided by rounding the #24 value to stock's displayed precision, **half-to-even** — confirmed against 15 independent cells including `1.84375 → "1.8438"` and `1.53125 → "1.5312"`, which only half-to-even reproduces. This suppresses 11,523 artefact cells across 137 tables.

A second bug fed the same failure: VCM Editor writes thousands separators, so `"6,042"` failed the numeric parse and four tables fell back to a table-wide precision far tighter than the display.

### Coverage — surplus, not loss

The stock sweep captured **576 scalars / 735 tables**; the #24 sweep holds **369 / 251**. VCM Editor in Advanced view across ECM+TCM exposes more than the older coalesced #24 file ever contained. **That surplus is extra stock coverage, not missing #24 data.**

Critically, the axle, tyre and AFM parameters are **absent from the swept #24 file entirely** — `data/2010_silverado_24.cal.json`, the hand-entered tune sheet, is their only source. Its stock claims are checkable against the independent sweep on 36 WOT cells and agree on **36/36**, which is what makes it trustworthy enough to carry the five axle/tyre changes.

| Classification | Count | Meaning |
|----------------|------:|---------|
| `changed` | 11 | #24 changed it |
| `stock_only_tune24_unmeasured` | 690 | read in stock, **no #24 reading at all** — UNKNOWN, not unchanged |
| `tune24_only_stock_unmeasured` | 6 | read in #24, not captured by the stock sweep — stock side UNKNOWN |
| `unchanged` | 610 | #24 left it identical to stock |

The 690 unmeasured parameters are **not** evidence that #24 left them alone. They are parameters no #24 reading covers. Missing is recorded as missing.
